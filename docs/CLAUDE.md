# Docs

- Most of these documents are for the product owner. Anything the owner has to do is written as numbered steps, for a reader with limited technical skills.
- Write plainly, the way a colleague would explain something out loud. When a person acts, make the person the subject. Otherwise use "is", "has", "there is" or a plain passive. Do not give a thing or a program an action verb to make the sentence sound active.
- Leave out emphasis words (always, every, each, only, never, whole, full, simply) unless the sentence is false without them. Do not build sentences for rhythm, and do not put a list of three inside a sentence. Headings name what the section contains.
- The full rules are in the language-standard skill. An independent agent reviews new text before it is merged.
- Decision records go in `decisions/`, one file for each decision, named with the next number and a short name (`0003-short-name.md`). They are written in the MADR format, with `status`, `date` and `decision-makers` at the top, as in `decisions/0001-public-code-private-content.md`.
- Course material does not go in these documents. For an example of a word or sentence, use made-up text or text from the fixture pack.
